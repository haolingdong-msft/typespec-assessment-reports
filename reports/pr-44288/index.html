Expected

Use the documented parent-resource private endpoint templates while evolving operation scope and parameters in a way that preserves existing versioned clients.

Evolving APIs — Introduction and Add a parameter to an operation in v2
Versioning allows you to evolve your API without breaking existing clients. By using versioning decorators, you can specify when resources, operations, or properties are added, removed, or changed.
Private endpoints — Adding Private Endpoint Operations to Your Resource Interface and Available Operations
Create an alias for your private endpoint operations using the `PrivateEndpoints` interface template. The operation table models custom patch and delete as `update is Ops.CustomPatchAsync<ParentResource>;` and `delete is Ops.DeleteAsync<ParentResource>;`.
Documented TypeSpec example
updateConnection is PrivateEndpointOps.CustomPatchAsync<Employee>;
deleteConnection is PrivateEndpointOps.DeleteAsync<Employee>;
ARM resource operations — Synchronous and Asynchronous APIs
CreateOrUpdate (PUT), Update (Patch), Delete, and Action (POST) operations over a resource may be either synchronous or asynchronous. Asynchronous operations return an initial response before the operation fully completes, and support long-running operation (LRO) polling.
ARM long-running operations — ARM LRO introduction, PATCH defaults, and DELETE defaults
Each header model accepts a `FinalResult` parameter that indicates the type of the logical result of the operation. It is important that this value matches what the operation actually returns. The headers appear in the `202 Accepted` response for PATCH, DELETE, and POST operations.
